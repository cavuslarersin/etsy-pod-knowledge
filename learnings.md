## 2026-09-05
- **Etsy SEO 2026 shift: buyer-behavior signals now weighted heavily** — click-through rate, add-to-cart rate, and purchase-completion relative to search impressions matter more than before. Keyword relevance (title > tags > category/attributes) is still foundational, but engagement now compounds on top of it.
- **Title guidance**: front-load concrete traits (color/material/size/occasion) at the start of the title; move subjective filler words ("beautiful", "perfect") out of the title into description/tags instead.
- **Shipping-price visibility penalty (US domestic)**: listings with a shipping price above $6 see reduced search visibility. **Verification note (2026-09-05):** don't compare this to Printify's own displayed "USD X.XX" cost/shipping figures in its pricing table — those are Printify's internal fulfillment-cost estimate, a different number from the buyer-facing charge. Check the ACTUAL Etsy shipping profile's `primary_cost` (via `get_shipping_profiles`) converted at the real current USD/TRY rate instead. Checked on UpCreateDesign: its US-domestic profile charges 242 TRY (~$5.00 at ~48.4 TRY/USD that day) — safely under $6, no action needed there. Still worth checking on any other shop before assuming a problem.
- Customer-experience completeness (full About section, filled-out Shop Policies, review volume/quality) is an explicit ranking input, not just a trust nicety.
- Sources: mydesigns.io/blog/etsy-search-algorithm-update-2026, craftybase.com/blog/what-is-seo-on-etsy, insightagent.app/guides/etsy-seo-2026

## 2026-09-05 (later same day)
- **Free-shipping strategy implemented on UpCreateDesign's mug line as a pilot**: Etsy's "free shipping" badge is a real conversion/visibility lever, separate from the >$6 shipping-price penalty already logged above. Mechanism used: create a second Etsy shipping profile that's an exact clone of the shop's normal one except US-domestic `primary_cost=0` (keep EU/CA/rest-of-world rates unchanged, since only US free shipping is commonly worth it), then assign it to selected listings while raising item price just enough to keep true margin (item price minus product cost minus the now-absorbed shipping cost) at or above a 10% floor.
- **Gotcha: shipping-profile creation requires `origin_postal_code` and per-destination `min_delivery_days`/`max_delivery_days`** (not just carrier/mail_class) — Etsy's create-shipping-profile and add-destination endpoints reject requests missing these even though they're not obviously "required" from the docs. Copy them from an existing working profile via `GET /shops/{shop}/shipping-profiles/{id}`.
- **Gotcha: price cannot be changed via `PATCH /listings/{id}`** for listings that use the inventory/offerings model (which includes any listing with personalization) — that field is silently ignored. Price must be updated via `PUT /listings/{id}/inventory`, and the payload's `offerings` array must echo back each offering's existing `readiness_state_id` or Etsy rejects the whole request with "All offerings need readiness state." Safe pattern: `GET` the inventory first, map `offerings` to `{quantity, is_enabled, price: newPrice, readiness_state_id: o.readiness_state_id}`, then `PUT` it back.
- Sources: applied directly via Etsy Open API v3 (no blog source for this entry — implementation note from live work).

## 2026-09-05 (Placeit shape-matching abandoned as default)
- **Placeit cannot reliably find templates matching a shop's actual product shape — confirmed unusable as a default source for mugs/tumblers/similar items.** Tried scoped searches ("tumbler", "hand holding tumbler") on a real 20oz insulated tumbler product: a "Popular"-sorted generic search returned the flat design tiled onto a T-SHIRT template (wrong product type); a scoped, correctly-typed search still returned a tall screw-cap water-bottle silhouette standing in for the shop's actual short dome-lid tumbler shape. Printify's own Placeit landing panel even self-discloses: "All our mockups are for illustrative purposes only and is not an exact representation of the print area."
- **New default going forward: native platform mockups (generated directly from the real print file) are the primary AND default product-photo source, not a first-choice-when-convenient. Do not spend time searching Placeit for exact product-shape matches** — the hit rate is too low relative to the time cost. Placeit remains a narrow fallback only, and only with type+silhouette verified plus the usual zoom-in legibility check.
- **Confirmed: Printify's REST API has no mockup-generation or Placeit endpoint at all** (checked official API docs — only Shops/Catalog/Products/Orders/Personalization/Uploads/Events/Webhooks exist). Selecting a Placeit template is the one genuinely browser-only step in this whole workflow; everything before and after it (image upload, fetching the resulting image URL, verifying it, pushing it to Etsy, price/inventory/shipping changes) has a direct API and should always use it instead of the web UI.
- **Browser-automation recovery pattern, now standard: if a page stops responding (screenshot/zoom/get_page_text all time out for 10-15s+), don't keep retrying reads — navigate to the same URL again (fresh reload) and retry the action.** Reliably recovered every stuck-page case hit this session. Also: if closing a tab reports success but the next action then can't find any tab group, the group was torn down — recreate it (create-if-empty) and re-navigate rather than reusing the old tab id.
- **Real product-photo bug found and fixed on UpCreateDesign, worth checking on any shop: verify EVERY listing's actual rank-1 (cover) photo, not just that images exist.** A tumbler's Printify-native "close-up" mockup had the drinking straw crossing directly over the character's face — it had been sitting as the Etsy cover photo undetected. Fix pattern: compare the same design's other native angles (front/back/left/right/opened/close-up), pick the one with an unobstructed view, upload it to Etsy at rank 1 via direct API, then delete the old flawed image (uploading at rank 1 does NOT replace the old rank-1, it just adds a second image tied for rank 1 — the old one must be explicitly deleted via `DELETE /shops/{shop}/listings/{listing}/images/{image_id}`).
- **Reproducible browser-automation bug: clicking a checkbox inside Printify's native mockup-library "select an angle" grid can silently navigate the tab to `chrome://newtab/` instead of toggling the box** (seen with both ref-based and coordinate-based clicks). No workaround found this session beyond reload-and-retry a couple of times; if it keeps happening, accept the product's current mockup selection rather than spend more time — fewer verified-clean native angles beats none.
- **COMPLIANCE RISK (real bug found and fixed, 2026-09-05): a batch of 10 listings on UpCreateDesign had `who_made` wrongly set to `someone_else`** (script default), inconsistent with the shop's other listings correctly set to `i_did`. For an owner-designed, POD-manufactured item, `i_did` + a disclosed production partner is the accurate combination — `someone_else` falsely claims a different person/business made it. Worth checking on any shop: `GET /shops/{shop}/listings/active` and compare `who_made` across all listings for inconsistency, and confirm `GET /shops/{shop}/production-partners` + each listing's `production_partners` array is non-empty (the print platform must be disclosed). Note: Etsy's PATCH endpoint requires `who_made`, `when_made`, and `is_supply` to be sent together — fetch the listing first to get its current `when_made`/`is_supply` values before patching just `who_made`, or the call is rejected.
- **This file is now kept current automatically, twice a day**, by a Claude Code cloud routine (research-only, no shop credentials, watches sales-visibility, traffic/prominence tactics, AND account-safety/compliance topics — findings prefixed `COMPLIANCE RISK:` or `VISIBILITY:`). If you're reading this as a human or another agent: don't assume you need to run the research pass yourself first — check whether today's date already has an entry before doing a manual pass.

## 2026-09-05 (evening research pass)
- **COMPLIANCE RISK: Etsy AI-disclosure enforcement is live and actively removing POD listings.** Enforcement began Jan 14, 2026: any listing where generative AI meaningfully shaped the image, mockup, description, or design must (1) be disclosed with explicit AI mention in the listing description, (2) flip the "Made by [seller]" attribution to "Designed by [seller]" in the Creativity Standards dropdown. Multiple independent sources cite Q1 2026 enforcement stats of ~12,000 listings removed and ~8,500 warnings issued, with POD sellers (t-shirts/mugs/posters/stickers) taking the largest share, especially shops with entire undisclosed AI-generated catalogs. Non-disclosed listings can also be silently filtered out of search. Action: audit any UpCreateDesign listing whose artwork involved an AI image-generation step and confirm both the description disclosure and the "Designed by" flag are set.
- **COMPLIANCE RISK: Etsy's "original design requirement" now appears to exclude purchased/templated design files even under a valid commercial license — a real risk if any listings are built from purchased clipart/PNG bundles rather than fully original artwork.** Etsy's Creativity Standards previously allowed computerized-tool items "based on a seller's original design **or using a templated design or pattern**"; that carve-out has been removed (multiple sources reference this change, though reported effective timing is inconsistent across sources — cited variously as June 2025 and as part of the August 2026 Prohibited Items Policy update — so treat the date as unconfirmed but the substance as current). The distinction sources emphasize: Etsy is now asking whether the design is the seller's own creation, not whether the seller has permission/license to use it. Action: inventory which UpCreateDesign listings use purchased clipart/template bundles (even with commercial licenses) vs. fully custom artwork, since the former is now a plausible suspension trigger regardless of licensing.
- **COMPLIANCE RISK: IP/trademark enforcement is increasingly automated and bulk-filed.** Major rights holders now run automated complaint systems; Etsy often suspends listings on an IP flag before human review. Enforcement firms reportedly file bulk complaints, so a shop can receive dozens of takedowns in a single week if any listings reference protected characters/brands/sports-team names. Two verified IP strikes within a year is commonly cited as a de facto path to permanent suspension. Action: keep a running check for any listing that references a brand name, character, or sports team/league, even "inspired by" or unofficial framing — these are treated as infringing regardless of disclaimers.
- **Etsy Prohibited Items Policy update effective August 11, 2026 bans real animal fur (mink, fox, rabbit, badger, coyote, raccoon dog), no vintage exemption.** Not applicable to UpCreateDesign's current product lines (mugs/tumblers/apparel via POD) but worth a quick scan if the catalog ever expands into fur-trim or fashion accessories.
- **Etsy SEO/algorithm specifics not previously logged**: titles now have a soft ~70-character cap before the algorithm treats them as "keyword stuffed" (favor natural, readable titles under ~15 words, consistent with the front-loading guidance already logged above); new-listing recency boost window has reportedly shrunk to 14–21 days (down from ~30 previously), so relisting/renewing stale listings for a recency bump is less effective than before; Star Seller badge status now carries more algorithm weight shop-wide, not just as a trust badge on individual listings.
- **Etsy Ads added a "Listing Strategies" feature (~June 2026)** for sellers running Etsy Ads with a daily budget of $25+: lets you pick a per-listing goal (Greater visibility / Lower click cost / Efficient spending) rather than one blanket bidding approach. Worth considering if/when UpCreateDesign runs paid Etsy Ads at that budget tier.

Etsy's `who_made` API field has no distinct "Designed by" value (only `i_did`/`someone_else`/`collective`) — `i_did` stays correct when the seller directs the AI's creative output; the "Designed by" label multiple sources describe appears to be Etsy's own storefront UI relabeling based on the disclosure text + who_made combination, not a separate settable API field. ## 2026-09-06 (new-shop setup, hands-on session — not a research pass, operational findings from actually opening a second shop)
- **An Etsy API app can only authorize the SAME Etsy account that registered it.** Reusing an existing shop's `ETSY_API_KEY`/client_id to run OAuth against a DIFFERENT Etsy account (e.g. a brand-new second shop under its own separate login) fails with "the application... is not recognized" / "Only the app owner may authorize a seller app." Fix: register a second, independent app under the new account's own Etsy Developer portal (`etsy.com/developers/register`) — a credential/API-key action on an already-existing Etsy account, not account creation, so doable directly once the owner is signed into the new account in-browser. A freshly-registered personal app sits in **"Pending Personal Approval"** for some unpredictable period with no self-service approve/speed-up control anywhere in the dashboard — just recheck later. Keep the new app's keystring/secret in a separate `.env.<shopname>` file rather than overwriting the original shop's `.env`; both apps can share the same local OAuth redirect port (`localhost:3003`) since only one `oauth.ts` process binds it at a time (kill a stale listener — `EADDRINUSE` — before retrying).
- **A new Etsy shop can cause Printify to auto-surface a newly-connected store under an account that already has Printify linked to a different shop, with no explicit "Add new store" click by anyone.** Confirmed 2026-09-06: opening a second Etsy shop resulted in a generically-named "My Etsy Store" entry appearing in `GET /v1/shops.json` against the SAME pre-existing `PRINTIFY_API_TOKEN` (account-wide, not per-store) — no new Printify OAuth flow, no new token needed. Always check `GET /v1/shops.json` first before assuming a new Printify connection step is required for a second shop.
- **Building shop branding (logo/banner) as script-generated images and getting them into Etsy's web-only Shop Home editor**: the editor's real URL is `https://www.etsy.com/shop/{shopname}/edit` (guessed paths like `/your/shops/me/edit/appearance` 404 — read the shop's own public page's "Edit shop" link href instead of guessing). There's no direct "upload this local file path" browser tool for a plain `<input type=file>`; the working pattern is: serve the local file from a throwaway local static HTTP server → screenshot it in a spare tab → `upload_image` that screenshot id into the real file-input ref on the target page. For the image content itself, hand-authored SVG shapes rasterize fine via `sharp`, but embedded-font `<text>` does not (same librsvg gap as font-on-mockup work) — convert real Google-Fonts static TTFs (via the `fonts.googleapis.com/css2` → `fonts.gstatic.com` redirect, not a variable-weight font) to path outlines with `opentype.js`, and always wrap the resulting path-data string in an actual `<path d="...">` tag inside the `<g>` — a bare path-data string dropped directly inside `<g>...</g>` is invalid SVG and silently renders nothing.
- **A third-party seller-tool browser extension (EverBee, in the same category as eRank) can inject a persistent overlay panel that silently intercepts clicks meant for the real page underneath it**, redirecting them to the extension's own UI instead (opened an unrelated extension tab when a normal page link was intended). If a click's actual effect doesn't match its coordinates' expected target, suspect an injected overlay before suspecting bad coordinates — re-resolve the real element (`find`/`read_page` for its href/ref) and act on that directly rather than continuing to click that screen region.
