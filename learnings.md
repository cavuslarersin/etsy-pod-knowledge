## 2026-09-05 (consolidated — five same-day passes merged 2026-09-08 to control file length; no facts dropped)
- **VISIBILITY/SEO fundamentals**: buyer-behavior signals (CTR, add-to-cart rate, purchase completion vs. impressions) now weigh heavily on top of keyword relevance (title > tags > category/attributes), which stays foundational. Full About section + Shop Policies + review volume/quality is an explicit ranking input, not just a trust nicety. - **VISIBILITY: shipping-price penalty verification method** — US-domestic listings priced >$6 lose search visibility; check the Etsy shipping profile's actual `primary_cost` (via `get_shipping_profiles`), NOT Printify's own displayed cost-estimate table (a different number). ## 2026-09-06 (new-shop setup, hands-on session — not a research pass, operational findings from actually opening a second shop)
- **An Etsy API app can only authorize the SAME Etsy account that registered it** — reusing an existing shop's client_id against a different Etsy login fails ("app... is not recognized"). Fix: register a second, independent app under the new account's own Etsy Developer portal; it sits in "Pending Personal Approval" for an unpredictable period with no self-service speed-up. Keep each shop's keys in its own `.env.<shopname>` file; both can share one local OAuth redirect port since only one process binds it at a time.
- **A new Etsy shop can cause Printify to auto-surface it under an account already linked to a different shop, with no explicit "Add new store" click** — confirmed via a generic "My Etsy Store" entry appearing in `GET /v1/shops.json` against the same pre-existing account-wide `PRINTIFY_API_TOKEN`. Always check `GET /v1/shops.json` first before assuming a new Printify connection step is needed.
- **Getting script-generated branding images into Etsy's web-only Shop Home editor** (`https://www.etsy.com/shop/{shopname}/edit` — read the shop's own "Edit shop" link rather than guessing the path): no direct local-file-path upload exists for a plain file input, so serve the file from a throwaway local HTTP server → screenshot it → `upload_image` that screenshot into the real file-input ref. Hand-authored SVG shapes rasterize fine via `sharp`, but embedded-font `<text>` doesn't — convert real static (non-variable) Google-Fonts TTFs to path outlines with `opentype.js` and wrap the result in an actual `<path d="...">` tag, not a bare path-data string.
- **A third-party seller-tool browser extension (EverBee) can inject an overlay that silently intercepts clicks meant for the page underneath**, redirecting to its own UI. If a click's effect doesn't match its target, suspect an injected overlay and re-resolve the real element rather than re-clicking the same coordinates.
